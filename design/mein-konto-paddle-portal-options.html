Drei Integrationsoptionen im direkten Vergleich. Jede Karte zeigt links, was der Nutzer auf Mein Konto sieht, in der Mitte was technisch beim Klick passiert und unten Pro/Contra.

Aktion auf unserer Seite Aktion auf Paddle-Portal
Option A · Einfach

Statischer Portal-Link

Paddle vergibt eine permanente customer_portal_url pro Kunde. Wir speichern sie und linken direkt.

Was beim Klick passiert
1 Nutzer klickt „Konto bei Paddle verwalten" lifeflow
2 Direkter Redirect zur gespeicherten URL lifeflow
3 Paddle-Übersicht öffnet sich, Nutzer navigiert selbst zu „Kündigen", „Karte ändern" etc. paddle

Pro

  • Kein Backend-Call beim Klick — nur Link
  • Implementierung: ein Tag Arbeit
  • Kein zusätzlicher Failure-Mode

Contra

  • Keine Deep-Links — Nutzer muss in Paddle selbst suchen
  • URL ist dauerhaft gültig; wer sie kennt, kommt rein
  • Kein „Abo kündigen"-Button auf unserer Seite möglich
Option B · Empfehlung

Portal Session API

Backend erzeugt pro Klick eine kurzlebige Portal-Session mit Deep-Link zur konkreten Aktion.

So sieht „Mein Konto" aus

Mein Konto

E-Mailmax@example.de
PlanPro · 6 Monate
Nächste Zahlung15.12.2026
App öffnen Zahlung & Rechnungen verwalten ↗ Plan wechseln ↗ Abo kündigen ↗
Was beim Klick passiert (Bsp. „Abo kündigen")
1 Nutzer klickt „Abo kündigen", kleines Bestätigungs-Modal: „Zugang bleibt bis 15.12.2026" lifeflow
2 POST /api/account/portal-session mit action=cancel lifeflow
3 Server ruft Paddle /customer-portal-sessions, bekommt kurzlebige URL lifeflow
4 Redirect direkt auf den Kündigen-Screen — kein Suchen nötig paddle

Pro

  • Echte Deep-Links pro Aktion — UX deutlich klarer
  • Sessions sind kurzlebig und an User gebunden
  • Sauberes Tracking: wer hat wann Kündigen geklickt
  • Rechtlich klar: Button auf eigener Seite + sichere Weiterleitung

Contra

  • Ein Paddle-API-Call pro Klick
  • Eigener Endpoint inkl. Auth + Error-Handling nötig
Option C · Hybrid

Statischer Link + Cancel-Deep-Link

Übersicht per permanentem Link, nur das Kündigen läuft über die Portal Session API.

So sieht „Mein Konto" aus

Nächste Zahlung15.12.2026
App öffnen Zahlung & Rechnungen verwalten ↗ Abo kündigen ↗
Zwei Mechanismen parallel
A „Zahlung verwalten" → direkter Redirect zur permanenten Portal-URL paddle
B „Abo kündigen" → Bestätigungs-Modal, dann Portal Session API mit cancel-Deep-Link paddle

Pro

  • Spart API-Calls für den häufigen Fall (Rechnung ansehen)
  • Kündigen bleibt explizit getrackt + Deep-Link

Contra

  • Zwei Mechanismen zu pflegen — mehr Code, mehr Test-Aufwand
  • Permanente URL muss trotzdem sicher gespeichert werden
  • Inkonsistente Sicherheits-Posture (mal Session, mal statisch)
Hinweis zu iframe-Embedding: Paddle setzt X-Frame-Options: DENY — das Portal kann nicht in unsere Seite eingebettet werden. Es bleibt in allen drei Optionen Redirect oder neuer Tab. Empfehlung: neuer Tab, damit „Mein Konto" beim Zurückkommen ohne Reload sichtbar ist.
